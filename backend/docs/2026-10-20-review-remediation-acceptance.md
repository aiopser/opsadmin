## 部署

1. 更新前后端代码，并安装项目锁定依赖。数据库操作在后端目录执行。
2. 执行 `poetry run python manage.py migrate`。本轮新增 `jobs.0019_workflowrun_failure_alert_context`；较早的菜单/云资产修复迁移也需部署到位。
3. 重新部署前端构建产物，重启 API、Celery Worker 和 Beat。不要只更新前端或只重启 Worker。
4. 如需检查部署版本，在 API 与各 Worker 配置相同的 `DEVOPS_RELEASE`（版本号或提交标识；也支持 `COMMIT_SHA`）。未设置或旧 Worker 未上报时，界面会明确显示无法确认，不会伪报一致。
5. 历史云资产需重新读取并确认同步，才能采集之前未保存的 CPU、内存、磁盘、地域及 EIP。已有 Windows 主机不会自动覆盖人工维护的连接协议，请按实际服务配置。

## 手工验收

使用测试账号、测试资产与测试通知渠道。

| 场景 | 操作 | 应见结果 |
| --- | --- | --- |
| 角色撤权 | 普通用户使用仅由一个角色授予的 API；管理员停用该角色后再次访问 | 原权限被拒绝；恢复角色后对应权限恢复 |
| 个人资料 | 个人中心修改昵称、电话；接口额外提交权限字段 | 正常资料可保存；额外权限字段返回 400，任何字段都不应部分写入 |
| 主机编辑 | 测试主机内存设 512/1536 MiB，仅修改名称 | 名称更新，内存保持原值；列表不再把容量取整 |
| 关联失败 | 通过 Network 拦截关系读取请求，再打开编辑；或提交非法关联 ID | 不应带空标签继续保存；后端返回错误时旧分组、标签完整保留 |
| 分页与布局 | 主机翻至第 3 页后切分组；在 1366×768 与窄窗口查看主机、通知、参数编辑页 | 页码回到 1；表头/内容按规则对齐；弹层不超出窗口；参数表头与字段对齐 |
| 云连接 | 阿里云账号只给主机查询权限、不授磁盘查询；选择多个测试区域 | 主机查询通过、磁盘查询失败分别可见；原始密钥不出现在响应中；未测区域明确列出 |
| 云差异 | 读取已有云主机；展开变更行；排除未变化主机后确认 | 看到旧值→新值及正确容量；未变化实例不冒充更新；只同步所选主机 |
| 确认期间变化 | 获取清单后在另一页面修改该主机 CPU，再确认原清单 | 要求重新读取并核对，不按过期差异继续提交 |
| 同步闭环 | 提交云同步后打开同步记录 | 排队→执行→终态自动更新，关闭后停止刷新；完成后可看到更新资产和最近同步时间 |
| 一次性调度 | 过期时间设为执行时间；已完成任务按旧时间重新启用；删除被任务引用的流程 | 均给出明确阻止原因；不会显示启用却无法执行或触发 AttributeError |
| 通知可靠性 | 失败告警等待发送时重试原运行；另测冻结渠道删除 | 原告警仍保留当时原因；渠道缺失明确失败，不发送到模板后来绑定的另一渠道 |
| 环境检查 | 健康页查看 SDK/密钥/版本状态；设置不同的 API 与 Worker 版本标识 | 缺失/格式错误可见；版本不一致给出提示；未报告时显示未知，不伪报正常 |
| 配置生效 | 搜索界面显示的配置名称；打开上述未接入项 | 搜索结果正确；未生效项不可误编辑且有说明 |
