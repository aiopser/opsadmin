# Ansible 资源变量与快速执行

脚本、Playbook 资源编辑中的 `extra_vars` 是该资源版本的 Ansible 变量默认值。快速执行时，同名变量覆盖默认值，未填写的默认变量保留。Module 资源只维护模块名称和参数说明，实际参数及变量在执行时填写。覆盖按顶层键进行，对象不会递归合并。

例如资源默认值为 `{"service_name":"nginx","port":80}`，本次填写 `{"port":8080}`，Runner 收到的业务变量就是 `service_name=nginx`、`port=8080`。

Module 的「模块参数说明」使用 key-value 行：Key 是参数名，Value 是说明文字，例如 `name → 服务名称，如 nginx`、`state → 目标状态：started / stopped`。可以添加和删除，重复参数名或缺少说明不能保存。说明随资源版本发布，在快速执行的「参数说明」中显示，不作为实际执行值，也不触发 extra_vars 必填或类型校验。

Module 新版本没有默认模块参数、额外变量和高级配置入口。实际值在快速执行或流程步骤中填写。已有发布版本不原地修改；旧版本保存的默认值仍兼容，基于旧版本编辑并发布的新说明版本不再携带这些隐藏默认值。

模块支持 `shell` 等短名称与 `ansible.builtin.shell` 等完整名称。快速执行支持 JSON 对象与原有 `key=value` 输入，含空格的 key=value 值需要引号，例如 `msg="hello world"`。`shell`、`command`、`script`、`raw` 仍支持原始自由命令，包括 `{ echo hello; }` 这样的 Shell 分组。JSON 对象则按模块原生参数解释，例如 shell 可用 `{"cmd":"echo hello","chdir":"/tmp"}`。JSON 对象与 key=value 参数中的重名键会被拒绝。历史资源版本的默认参数仍使用 JSON 传递；新说明版本不自动带入参数值。

快速执行选择资源库时绑定已发布版本；Playbook 和脚本正文必须与该版本一致。变量默认值、兼容校验、输出规则、提权设置和超时写入本次运行的图快照；资源后续停用或归档不改写已有运行。运行重试沿用快照。

新资源不再要求配置参数模式或输出提取器。已有版本的参数校验和输出提取保留兼容。新输出规则在流程步骤的高级配置填写：

```json
[{"name":"release","pattern":"RELEASE=(.*)","group":1,"type":"string"}]
```

留空继承历史资源输出规则，填写 `[]` 关闭规则提取。规则作用于每台主机的标准输出。单主机步骤可用 `nodes.步骤标识.outputs.release`；多主机步骤通过 `outputs.hosts` 读取对应主机的输出。

验收建议：

1. 发布带默认变量的脚本和 Playbook，本次仅覆盖一个变量，确认其他默认值仍生效。
2. 预览后修改本次变量再提交旧确认凭据，确认被拒绝；重新预览后可提交。
3. 选择资源库 Playbook，确认正文只读；在线编写时不绑定资源版本。
4. 模块参数和额外变量分别生效，显式清空模块参数不会恢复原默认值。
5. 配置步骤输出提取，后续步骤可引用；非法正则在保存或发布前被拒绝。

模块名保存到 `automation_command_version.module_name`，参数说明保存到同表的 `parameter_docs` JSON 字段；脚本和 Playbook 正文仍保存到 `content`。新 Module 版本不再借用 `content` 或 `argument_schema` 保存模块名和说明。迁移会复制旧数据，保留旧发布版本的原字段与运行快照，以兼容历史执行。

更新代码时需先备份数据库并执行迁移 `0012_module_fields`，再重启后端 API 和 Celery Worker，并部署最新前端。部署步骤见 [Module 字段迁移说明](2026-10-26-module-field-migration.md)。

## 执行资源编辑与版本管理

- Playbook 直接编辑 YAML 与 extra_vars；当前 Git 入口只导入单文件，仓库的 roles、files、templates 不会随之导入。保存校验 YAML 结构，不等于执行环境中的 Ansible 完整语法检查。
- Module 填写 Ansible 模块名及自主维护的 key-value 参数说明；不提供默认模块参数、extra_vars、高级配置或 YAML/Git 文件导入。
- 脚本和 Playbook 的高级配置可调整执行超时、提权与检查模式支持。检查模式行为取决于模块及任务配置，不能保证完全没有变更。
- 列表区分「编辑信息」与「编辑内容」；无草稿时可基于已发布或归档版本创建草稿，正式保存前不会自动写入一个新版本。
- 首版本保存失败保留当前内容，再次提交复用已经创建的资源；取消后仍能在版本管理中补充草稿。
- 只有草稿可以编辑、发布、删除。发布、归档及草稿版本号分配使用同一父资源事务锁；发布失败不会丢失原已发布版本。已发布/归档版本不可从 API 直接删除，也不能通过直接创建 published 状态绕过发布。

## 流程编排中的原生参数

任务单参数只声明每次运行需要填写的值，不需要再做参数映射。脚本使用 `$变量名` 读取环境变量，Playbook 使用 Ansible 的 `{{ 变量名 }}` 读取 `extra_vars`。

步骤高级配置按类型提供可选覆盖：脚本「环境变量」填写 JSON 对象，Playbook「extra_vars」填写 JSON 对象，模块「模块参数」使用原生 `key=value` 或 JSON 对象。Playbook 参数内的原生 Jinja 表达式交给 Ansible 解析，平台不提前解析为流程表达式。覆盖顺序为资源默认值、任务单参数、步骤原生参数。Shell 环境变量只接受字符串、数字和布尔值，平台执行字段不可覆盖。

Jenkins 的「构建参数」支持流程变量表达式。编排不再提供其他类型的通用参数映射。API 继续使用结构化 HTTP 执行器，通知继续使用通知模板。


## 执行策略与超时的归属

| 配置位置 | 职责 |
| --- | --- |
| 执行资源 | 可复用内容、默认变量、默认步骤超时、提权和检查模式支持能力 |
| 集成资源 | 连接地址、认证、请求定义、请求超时、成功判断和输出提取 |
| 流程步骤 | 原生参数、输出提取、失败处理与最大尝试次数；可选覆盖步骤超时与平台主机策略 |
| 任务单 / 手动运行 / 定时任务 | 目标主机、执行节点池、连接网关、平台默认策略、并发、批次、失败比例、整个流程超时 |

主机策略默认继承任务运行设置；只有开启「单独设置此步骤」时才保存步骤覆盖。关闭后清除该步骤的策略覆盖，填写 0 的失败比例表示零容忍，留空表示继承。串行每次处理一台主机，并发固定为 1，不再提供批次输入。

Playbook 默认使用原生主机策略，保留正文中的 `serial`、`max_fail_percentage` 和 `any_errors_fatal`。需要平台统一控制批次和失败处理时，选择「平台执行策略」。原生策略的 Runner 并发数继承任务运行设置，不因平台串行策略被强制为 1。检查模式仍由 Runner 执行，必须由资源版本声明支持。

步骤超时留空（图中的 `timeoutSeconds: null`）使用资源默认值；显式填写则覆盖资源默认值。例如资源默认 60 秒，步骤填 120 秒，流程总超时 300 秒，该步骤最多可用 120 秒。整个流程只剩 30 秒时，该步骤最多运行 30 秒。无资源超时的集成步骤使用流程预算，API 自身的 HTTP 请求超时仍有效。超时和策略在运行创建时冻结；派发、租约、执行器从同一快照读取，重试不会读取模板的最新配置。
