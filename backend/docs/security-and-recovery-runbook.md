# 权限、秘密输入与执行恢复

更新：2026-10-24。本文对应当前代码；隔离自动测试不等于真实 Worker、MySQL、云账号或通知验收。当前验证结果见 [状态索引](current-status.md)。

## 授权边界

| 操作 | 必须满足的边界 |
| --- | --- |
| 新建、编辑用户 | API 权限；禁止写入 is_superuser、is_staff、groups、user_permissions、安全版本和锁定字段 |
| 分配角色 | 非超管只能授予自身权限及作业数据范围以内的角色；不能授予 admin 角色 |
| 高危执行 | 手动、任务单、定时、立即执行、重跑和节点重试统一授权；Worker 执行前按当前责任人重新校验 |
| 运行及子资源 | API 权限与本人/同部门/全部数据范围同时生效；日志、主机结果、attempts 使用同一范围 |
| 定时责任人停用、离职、失去权限 | 拒绝触发，记录原因；不会自动转给超管。由有权人员显式维护责任归属 |
| 资源申请人工核实 | provisioning.review 复核权限，且不得是原申请人或 apply 执行人；预览及确认都重新验证 |

用户管理权限不等于超级管理员授权。部门、角色或高危权限变更需复核其影响；不要通过直接修改数据库绕过服务校验。

## 登录和密码

`security.login.max_failures` 控制连续失败阈值（配置缺失时 5 次），达到阈值锁定 15 分钟。窗口结束后可以重新验证；成功登录清零计数。锁定通过数据库行锁更新，在隔离 MySQL 验收时需覆盖同一账号的并发失败。

通过用户管理创建账号或重置密码后，`must_change_password` 要求先改密。此时只开放当前用户、个人资料/改密、退出及必要路由配置接口；业务 API 被拒绝。完成改密后重新登录。重置密码只接受 PUT 请求正文的 password/new_password，禁止把密码放在 URL。

修改或重置密码会递增 `auth_version`，旧 access 和 refresh 均失效。历史不含版本的令牌仅在账号版本仍为 0 时兼容；不要用数据库直接更新 password 绕开 `set_password`。遗失超管访问时按受控运维流程在维护环境使用 Django 改密命令，并保留审计记录。

普通资料保存不会回写密码、会话版本和登录锁定列，避免并发旧对象撤销新密码。自动升级旧密码摘要使用旧摘要条件更新，保留首次改密要求和认证版本；如果并发重置已经生效，旧摘要验证不能覆盖新密码。

## 任务单、定时定义和运行中的秘密

流程输入 schema 的 `type=secret` 决定敏感字段。源定义与运行分别加密存储，API 只返回 `[REDACTED]`；密文字段不属于 API 数据。相同流程版本编辑时，脱敏占位符或省略秘密字段表示保留原值；提交新的值表示替换，空值表示清空并接受 required 校验。换版本后不能用旧占位符代替填写。

`jobs/0020_definition_secret_inputs` 会迁移已有明文定义；无法找到原流程版本的孤立定义保守地加密全部输入。迁移不可逆。升级前同时备份数据库和凭据加密密钥，并在隔离副本测试解密和运行；恢复数据库却遗失密钥无法恢复秘密。备份历史明文数据库同样要加密、限制访问和按保留策略处理。

不得将秘密打印到日志、通知、测试输出或工单附件。应用只能对明确标注的秘密字段执行脱敏；把密码放进普通 text/extra_vars 或脚本输出不会自动变成秘密参数。

## HTTP 发起幂等

预览返回 `executionRequestId`，确认时原样提交。任务单、定时立即执行、直接执行、脚本、Playbook、模块及历史创建入口复用同一确认标识。API 客户端也可发送 `Idempotency-Key`；两处同时填写必须一致。键绑定当前操作者、端点和请求载荷，成功结果与运行创建在同一事务提交。

回放仍执行当前 API 权限校验，详情动作也重新执行对象数据范围检查。原来能重试他人节点、后来失去相应数据范围的用户，不能用旧确认标识重新读取受保护响应。

| 情况 | 处理方式 |
| --- | --- |
| 双击或响应丢失后重发相同请求 | 返回同一次运行，响应头 Idempotency-Replayed 为 true |
| 同一键但载荷不同 | 409；重新预览后再确认 |
| 校验失败、没有成功受理 | 可修正后重试，失败不占用成功键 |
| 明确需要再运行一次 | 重新预览获得新键，不能复用旧键 |
| 兼容旧客户端不传键 | 保留旧行为，不承诺请求去重 |

请求摘要使用服务密钥 HMAC，响应加密保存在数据库。默认保留响应；可通过以下命令压缩超过 90 天的响应，先预览再执行：

```text
poetry run python manage.py compact_execution_requests
poetry run python manage.py compact_execution_requests --days 90 --execute
```

压缩只移除响应密文，永久保留去重键及摘要；旧请求返回 410 并要求查询执行历史，不会再次执行。不要直接删除这些记录来清理空间。此命令未自动定时部署；由部署方根据保留规则安排。用户删除时相关键随账号删除，审计保留另按组织策略处理。

## Worker 迟到、重试与取消

attempt_count 与 task ID 共同决定当前节点执行权。旧 attempt 的迟到输出、完成、失败或事件可保留历史归属，不得覆盖当前节点投影或推动下游。云同步终态与资源交付回读使用相应认领标识；超时回收后的旧 Worker 不得把失败重新改成成功。

失败节点重试会恢复因“前序步骤失败”阻断的下游，正常条件分支的跳过保持原样。重试会再次检查权限。先定位失败原因，检查命令是否已经对外部系统产生作用；节点去重不保证任意 Shell、HTTP 或外部平台的副作用恰好一次。

Worker 丢失或超时回收时，未开始的下游可能标记为 canceled。显式重试只恢复带有“从未开始”恢复原因的这些节点；用户主动取消和条件分支决定保持不变。冻结快照仍使用原主机地址与原凭据引用，实际执行前重新检查原凭据权限；资产改绑不能替代这次授权。

Jenkins 的“取消”表示停止本平台等待，已排队或开始的远端构建可能继续运行。需要停止远端构建时，由有权限人员在 Jenkins 查看 queue/build 并执行取消；不要把本平台 canceled 当成远端已经停止的证明。

## Terraform 结果未知的核实与结案

结果为 needs_reconciliation 时停止重复 apply。先核对申请、执行 attempt、Worker/云审计和 state 归档。普通回读只查询 state 中的实例，不创建云资源；state 恢复也不回滚云资源。

1. 恢复 API/Worker 所用的私有制品主存储、独立备份和相应 state 密钥。必要时使用已有 `provisioning_state_index --repair` 预览/修复保护；不上传自行编辑的 state 或实例 ID。
2. 在申请详情选择“人工核实”，由独立复核人生成预览。系统校验 apply 已发起、写租约已过期、最新 state 归属及两份保护副本，并向云 API 重新查询实例。
3. 核对实例数量、ID、地域、地址及状态，填写可追溯工单/云审计证据编号和核实说明；证据中不放凭据。
4. 确认时系统再次授权、核验 state 和云端观测。预览 15 分钟有效，任一控制状态、账号配置或实例观测变化都需要重新预览。
5. 成功后按真实观测纳入资产、增加 state_generation、废止旧执行/回读认领并写审计事件。查询申请事件确认证据记录；再次确认同一预览会拒绝。

接口为 POST `/api/v1/provisioning/requests/{id}/resolution-preview` 与 `/resolution-confirm`。无 state、实例未完整返回、缺少私网 IP、仍有写租约、备份不完整或权限失效时保持待核实，不能人工勾选“成功”。部分创建或完全没有 state 的场景需先恢复可信归档与云证据，本入口不会代替资源清理/销毁审批。

## 故障定位顺序

| 现象 | 先查什么 | 恢复边界 |
| --- | --- | --- |
| 运行长期排队、Worker 失联 | 队列配置、Worker 心跳、版本、Broker 连接、并发/租约 | 恢复 Worker 后查已有运行；不重复创建运行 |
| 云同步一直失败或超时 | 同步任务 ID、SDK、区域、只读权限、云请求 ID | 确认旧任务终态后重新读取；不用失败批次覆盖已有资产 |
| apply 连接断开、结果未知 | 云审计、attempt、state 主副本和备份 | 仅回读/人工核实；禁止盲目重跑 apply |
| state 解密失败或备份损坏 | key ID、密钥环、文件权限、摘要、独立备份 | 保留全部证据，使用可验证副本恢复；不覆盖原文件 |
| 磁盘满或制品过多 | 私有存储容量、制品索引、日志保留策略 | 使用现有 GC 预览；活动/未知状态/state 不手工递归删除 |
| 通知未收到 | 发送记录、模板场景、变量预览、渠道响应、机器人策略 | 修正后按发送记录重试；不重跑业务来测试通知 |

升级维护窗口先停止接收新写任务与 Beat，等待/核实在途任务，备份后迁移，再以同一版本启动 API、ASGI、所有 Worker 与 Beat。队列里旧代码已经启动的进程不会因文件更新自动更换逻辑。完整演练清单见 [部署手册](deployment.md) 与 [云 IAM 验证](cloud-iam-validation.md)。
