# 菜单图标编辑与历史路由兼容修复

## 原因

- 编辑器把旧组件 system/user/index 当成无法识别的组件，保存时可能丢失组件值；页面选项还错误加入 User、Role 等路由名称，容易产生 view.User 这类不存在的页面组件。
- 编辑器初始化时的路由名称监听会改写路径和国际化键（前一轮已修复）。
- 多参数路径通过 split('/:') 拆分，只保留了第一个参数片段。

## 修复

1. 区分用户真实修改与编辑器初始化：图标、名称等展示字段的修改原样保留组件与路由路径。
2. Layout、ParentView、旧页面路径正确显示；页面候选项以真实组件为准，不再插入路由名称。
3. 旧页面选择不会再自动拼出 view.system/user/index；多参数路径完整保留。
4. 后端动态路由对已知旧组件前缀错误提供兼容，并对系统管理的 User、Role、SysMenu、Dept、Dict、Config 旧别名恢复对应的 manage_* 页面与路径。仅匹配确定的内置别名及其名称，不按任意图标或中文标题猜测路由。

## 生效操作

同时部署前端产物和后端 API，重启 API 服务，然后刷新浏览器重新获取动态路由；若旧标签页仍留有旧路径，退出并重新登录。无数据库迁移，也不需要重新播种菜单。

本次兼容发生在动态路由输出阶段，不批量修改既有数据库菜单记录。若部署后还有其他自定义菜单失效，需要查看该菜单记录的组件、路由名称及路由路径，不能按内置菜单规则强行覆盖。
