# Consul Template 实现审查

本报告记录最初实现的审查结果。用户随后确认整文件接管；读取、差异与下发保护的当前说明见 [现有文件接管](consul-template-file-takeover.md)，以下描述不代表改造后的全部现状。

当前实现是单文件下发与 reload，尚未达到此前约定的模板版本、预览发布、部署管理和执行记录闭环。本轮未修改业务代码，未执行真实主机下发或危险命令。

## 必须修复的问题

### P1：操作权限与实际风险不匹配

- 位置：`backend/apps/consul/templates.py:56`、`:94`。
- reload 校验只约束首个可执行文件和 token 字符，不约束操作和服务对象。隔离环境只调用校验函数，已确认 `systemctl reboot`、`systemctl stop sshd`、`pkill -9 sshd` 均被接受；未执行这些命令。
- 路径校验同样接受 `/etc/sudoers`，没有限定配置目录。之后代码把动态生成的任意文件写入脚本标为 LOW，绕过已有高危执行权限要求。实际影响取决于目标 SSH 账号权限。
- 必须限制可写目录和可执行动作/服务对象，考虑 HCL 内部可配置执行命令的能力；不能仅靠首 token 白名单就把所有内容判为低危。校验节点/执行人权限、部署审批和运行权限应形成闭环。

### P1：覆盖配置后失败无法恢复

- 位置：`backend/apps/consul/templates.py:70`。
- 脚本渲染临时文件后直接 `mv -f` 到正式路径，再执行 reload；没有内容校验、原文件备份或失败恢复。trap 仅删除临时文件。
- 无效配置或重载失败后，旧文件已丢失，线上正式路径留着错误文件。临时文件权限也没有恢复为原文件的属主/权限。
- 必须先验证候选配置，保留原文件及元数据，失败时恢复并记录恢复结果；明确首次创建没有旧文件时的处理。文件替换成功与应用实际重载成功需要分别记录。

### P1：下发状态与运行结果脱节

- 位置：`backend/apps/consul/views.py:314`、`backend/apps/consul/models.py:24`。
- 提交运行后只写 `pending` 与“已提交”，没有成功、失败或取消状态回填，也没有持久关联 run 的字段。模型里的 success/failure 没有生产写入路径。
- 因此刷新模板列表不能知道真实下发结果。需持久关联部署记录和作业运行，用任务完成/恢复路径更新状态，防止较旧运行覆盖较新部署结果；不能把入队当作成功。

### P2：新增接口未进入共享契约检查

- 位置：`frontend/scripts/observability-api-contracts.cjs` 与 `docs/integrations/observability-api-contracts.json`。
- `pnpm test:contracts` 当前为92通过、1失败。失败项提示 monitoring 服务新增8个函数没有样例，其中4个是 Consul Template 的列表、保存、删除、部署；其余是 Consul KV 函数。
- 需要补充实际请求样例和共享契约，再验证后端路径、方法、权限、响应。不能删除检查或绕过测试。

## 与已确认需求的差距

1. **缺少模板生命周期。** `ConsulTemplateFile` 只有唯一 content，编辑会直接覆盖。没有草稿/不可变发布版本、Go Template 渲染预览、配置差异、版本绑定与回滚。执行时临时生成的 CommandVersion 不是模板版本管理。
2. **缺少明确的部署对象。** 模板内容、目标主机、输出路径和 reload 命令混在同一条记录；没有独立部署记录、运行进程状态或现有 Consul 连接引用。
3. **HCL 配置与 Go Template 正文没有区分。** 编辑器示例是 HCL，引用远端 `.ctmpl` 文件，但平台没有对应模板源文件的管理与下发闭环。首次部署不能假定该文件已存在。
4. **菜单未按约定实现。** `backend/apps/permission/seeds/menus.py:42` 仍将“模板配置”放在监控管理下。需要独立一级“Consul Template”，下设模板管理、部署管理、执行记录，并通过后端菜单控制。

## 其他前端细节

- 主机下拉使用通用主机接口，未按 Linux 过滤或禁用 Windows/停用主机；占位说明却称“搜索 Linux 主机”。不应直到保存或下发时才拒绝。
- 新建记录显示“待确认”，后端 pending 的业务含义是“待下发”，需要区分未部署、排队、执行中和终态。
- 当前列表一次读取全部模板、前端切片分页。模板量增长后应改为服务端分页。
- 下发后跳转作业运行详情依赖额外的运行查看权限，模板部署按钮的权限映射未提供运行查看权限；需按现有运行数据权限方式设计可访问的记录入口。

## 验证证据与下一步

- 隔离执行 `poetry run pytest apps/consul/test_consul.py`：19 passed。这些测试没有覆盖以上失败恢复、终态回填和危险动作拒绝问题。
- 执行 `pnpm test:contracts`：92 passed、1 failed，原因见上。
- 对 reload 与路径校验函数做了无副作用调用验证；未连接真实 Consul、目标主机或执行任何 reload/reboot/kill 命令。

建议先修权限边界、配置恢复和结果回填，再补版本与预览发布。验收必须覆盖普通角色、重复/并发下发、无效配置、reload 失败、任务中断、旧运行晚到，以及回滚后的实际文件和进程状态。
