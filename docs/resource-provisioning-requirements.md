# 主机资源申请与交付

状态：首版前后端已实现，尚未部署；真实云创建与浏览器视觉验收待完成。具体交付边界见 `backend/docs/resource-provisioning-deployment.md`。

## 目标

运维或没有专职运维的小团队通过标准模板申请云主机，清楚确认变更范围，经确认或审批后执行，最终通过云 API 核实真实资源并纳入资产管理。

主路径：选择资源模板 → 填写参数 → 生成变更计划 → 确认或审批 → 执行 → 云 API 回读 → 纳入资产管理。

## 功能边界

- 现有资产接入继续承担已有资源的发现与同步。
- 新增资源申请承担新建主机的交付，不直接在主机资产表中伪造创建结果。
- 资源模板与现有脚本、流程模板区分，发布版本不可原地修改。
- 建议首期支持阿里云 ECS、腾讯云 CVM；VMware、OpenStack、PVE 后续按相同交付契约扩展。此范围是建议，并非已确认的全部支持列表。
- 采用 Terraform 生成与执行保存计划；首版使用专用 Worker、每申请隔离的本地 state 与私有加密归档，远端 backend 后续扩展。
- 首期以新建主机为边界，变更计划出现删除或替换操作时拒绝执行；扩容、变更、销毁另行设计。

## 页面与交互

- 资源配置增加资源模板及版本管理，提供参数约束和适用云平台说明。
- 任务系统增加资源申请列表；主机资产可提供申请主机入口，使用后端动态菜单与路由。
- 申请采用步骤条，分别展示模板与账号、规格与网络参数、变更计划、确认审批及交付结果。
- 计划明确展示云账号、地域、数量、规格、镜像、磁盘、网络、安全组及将创建的资源；数量不能替代资源明细。
- 申请详情展示计划、审批记录、执行日志、云资源 ID 和纳管结果；沿用现有后台的字体、表单、按钮及状态视觉规范。
- 执行失败与纳管失败分别显示，提供排查和后续处理入口。

## 一致性与安全规则

1. 申请冻结模板版本、参数、账号、地域与执行器版本，凭据明文不进入业务快照、日志或前端响应。
2. 资产读取权限与资源创建权限分别授权；复用云账号身份并不意味着自动拥有资源创建权限。
3. 确认或审批绑定确定的计划摘要与完整性校验值。修改参数、模板版本、账号或重新生成计划后，旧确认与审批失效。
4. 服务端依据策略决定直接确认或审批；前端不能通过修改提交字段绕过审批。审批人与申请人是否可相同须由服务端策略约束。
5. 执行已确认的保存计划；计划过期、执行前权限失效、状态冲突时拒绝执行并要求重新生成计划。
6. 执行使用隔离工作目录、受控模板和固定依赖；状态与计划可能包含敏感信息，需加密存储、访问控制和保留期限。
7. 同一申请防重复提交，状态与执行任务有锁和幂等约束；并发申请的状态文件不得互相覆盖。
8. 执行部分成功或进程中断后先核实云资源与状态，不能盲目重试创建或自动销毁。
9. 创建完成通过云 API 回读，以云账号与云资源 ID 建立资产唯一身份，复用已有资产规范化与同步逻辑。
10. 云 API 暂时不可见时进入待核实状态并有界重试。资源已创建但纳管失败时，重试仅回读与纳管，不再次创建。
11. 审计关联申请、计划、确认或审批、执行和资产；失败通知复用现有通知渠道及发送记录。

## 建议的状态划分

- 计划：生成中、可确认、生成失败、已过期。
- 审批：无需审批、待审批、通过、拒绝、已失效。
- 执行：未开始、排队、执行中、成功、失败、结果待核实。
- 纳管：未开始、回读中、成功、失败。

分别保存这些状态，避免单一“成功”掩盖已创建但未纳管的情况。

## 必须验收

- 修改已审批参数后不能继续执行旧审批对应的申请。
- 无创建权限、跨账号引用、已禁用账号或审批缺失均被后端拒绝。
- 重复点击及任务重复投递不会创建重复主机。
- 部分创建成功、Worker 中断、回读暂时不可见均能核实真实结果。
- 纳管重试不重复创建；纳管资产与后续资产同步能识别为同一资源。
- 日志、计划展示、错误、审计及通知不泄露密钥。
- 资源创建成功但纳管失败，在列表和详情中能明确区分。
