## 1. 新增接口

### 1.1 获取页面组件列表

- **对应前端**：`fetchGetAllPages()`，菜单管理弹窗「页面」下拉选项
- **方法路径**：`GET /api/v1/pages`
- **鉴权**：JWT Bearer

**响应 200**

```json
[
  "home",
  "manage_user",
  "manage_role",
  "manage_menu",
  "manage_user-detail",
  "about"
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| （数组元素） | `string[]` | 页面组件名（即视图名，**不带** `view.` 前缀）。前端会拼装为 `layout.base$view.manage_user` 存入菜单 component 字段 |

**备注**：前端构建期（elegant-router）已知全部页面，也可由前端本地生成。若后端实现成本高，可协商改由前端处理，**本接口可降级为 P1**。

### 1.2 批量删除用户

- **对应前端**：用户管理表格「批量删除」按钮（当前为前端占位）
- **方法路径**：`DELETE /api/v1/users/batch`
- **鉴权**：JWT Bearer

**Body（application/json）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| ids | `number[]` | 是 | 用户 ID 列表，非空 |

```json
{ "ids": [1, 2, 3] }
```

**响应**：`204 No Content`

**错误**

| 状态码 | 场景 |
|---|---|
| 400 | ids 为空数组 |
| 403 | 无权限（需管理员角色） |

**备注**：也可采用 `POST /api/v1/users/batch-delete`，由后端定夺，前端配合调整。

### 1.3 获取角色菜单权限（回显）——调整现有接口

- **期望响应 200**

```json
{
  "menu_ids": [1, 2, 5, 8, 9],
  "home_path": "/home"

```

| 字段 | 类型 | 说明 |
|---|---|---|
| menu_ids | `number[]` | 该角色勾选的菜单 ID 列表（含目录/菜单/按钮） |
| home_path | `string \| null` | 该角色的默认首页路由路径，如 `/home`；未设置则 null |

## 2. 模型字段扩展

### 2.1 Role 角色表（影响 `/api/v1/roles` 全套接口）

**背景**：前端路由权限依赖角色编码（如路由 meta `roles: ['R_ADMIN']`），现有 Role 仅有 `name`，**缺 code 前端无法做权限控制**。

| 新增字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| code | `string(64)` | 是 | 角色编码，全局唯一，如 `R_ADMIN`、`R_SUPER`。前端用于路由权限匹配 |
| description | `string(255)` | 否 | 角色描述 |
| is_active | `boolean` | 是 | 启用状态，默认 `true` |

**扩展后的 Role 示例**

```json
{
  "id": 1,
  "created_at": "2026-08-01T10:00:00Z",
  "updated_at": "2026-08-10T10:00:00Z",
  "name": "管理员",
  "code": "R_ADMIN",
  "description": "系统管理员，可管理用户和菜单",
  "is_system": false,
  "is_active": true,
  "permission": [1, 2, 3]
}
```

**联动要求**：
- 用户角色下拉（前端 `fetchGetAllRoles`）需返回 `id` / `name` / `code`
- 用户表单提交的用户角色用 **code** 还是 **id** 需明确（前端现有 `userRoles: string[]` 为编码数组，见 2.3）

---

### 2.2 Menu 菜单表（影响 `/api/v1/menus` 全套接口）

**背景**：前端菜单模型（`Api.SystemManage.Menu`）含路由元信息全量字段，现有后端 Menu 缺以下字段。

| 新增字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| icon_type | `integer` | 否 | 图标类型：`1`=iconify（如 `carbon:user`）、`2`=本地 svg 图标。默认 `1` |
| i18n_key | `string(128) \| null` | 否 | 国际化 key，如 `route.manage`。不填则前端直接用 title |
| href | `string(128) \| null` | 否 | 外链地址（菜单点击跳转外部 URL 时使用） |
| multi_tab | `boolean` | 否 | 是否允许多标签页打开，默认 `false` |
| fixed_index_in_tab | `integer \| null` | 否 | 固定在标签栏的序号（现有 `affix` 为 boolean，无法表达序号，建议以此字段替代/并存） |
| query | `object \| null` | 否 | 路由 query 参数（JSON 对象），如 `{"id": "1"}` |
| constant | `boolean` | 否 | 是否常量路由（不参与权限过滤），默认 `false` |
| is_active | `boolean` | 是 | 菜单启用状态，默认 `true` |

**现有字段映射对照（无需改动，前端负责转换）**

| 前端字段 | 后端现有字段 | 转换 |
|---|---|---|
| menuType `'1'目录/'2'菜单` | menu_type `'C'/'M'/'B'` | 枚举转换 |
| parentId | pid | 直接 |
| menuName | title | 直接 |
| routeName / routePath | name / path | 直接 |
| keepAlive | no_cache | **取反** |
| hideInMenu | hidden | 直接 |
| activeMenu | active_menu | 命名风格转换 |
| component | component | 后端存视图名（如 `manage_user`），前端拼装 `layout.base$view.manage_user` |

**按钮权限建模（已落地 ✅）**：
按钮不再以 `menu_type='B'` 的菜单子节点表达，而是采用**独立的 MenuButton 模型**（表 `permission_menu_button`），挂在所属菜单的 `buttons` 字段上，与前端 `Api.SystemManage.MenuButton { code, desc }` 完全对齐：

- 菜单接口（`GET/POST/PUT /api/v1/menus`）的请求体与响应均携带 `buttons: [{ code, desc }]` 数组，提交时全量覆盖同步（增/删/改描述）
- 每个按钮自动维护一个 `type='button'` 的权限标识（`Permission.code` = 按钮编码），按钮触发的 API 权限仍绑定在按钮上，角色分配时照常展开进 Casbin
- 菜单删除时按钮级联删除；`menu_type` 枚举仅保留 `C`（目录）/ `M`（菜单）
- 存量 B 类型菜单行已通过数据迁移（`0022_menu_button_model`）自动转换为 MenuButton 记录

**角色菜单/按钮分配接口（同步调整 ✅）**：

- `GET /api/v1/roles/{id}/menu-ids` 响应改为 `{ "menuIds": ["1", ...], "buttonIds": ["5", ...] }`
- `PUT /api/v1/roles/{id}/menus` 请求体改为 `{ "menuIds": [...], "buttonIds": [...] }`（buttonIds 为 MenuButton ID，替代旧 `perm:` 前缀格式）

## 3. 结构适配：动态路由

### 3.1 GET /api/v1/menus/routes（✅ 方案 A 已落地）

**实现说明**：后端直接输出 soybean-admin 的 `UserRoute` 结构（嵌套树 + meta 路由元信息），前端零转换。

**响应 200**

```json
{
  "routes": [
    {
      "id": "1",
      "name": "manage",
      "path": "/manage",
      "component": "layout.base$view.manage",
      "meta": {
        "title": "系统管理",
        "i18nKey": "route.manage",
        "icon": "carbon:cloud-service-management",
        "order": 9,
        "keepAlive": false,
        "hideInMenu": false
      },
      "children": [
        {
          "id": "2",
          "name": "manage_user",
          "path": "/manage/user",
          "component": "view.manage_user",
          "meta": {
            "title": "用户管理",
            "i18nKey": "route.manage_user",
            "icon": "ic:round-manage-accounts",
            "order": 1,
            "keepAlive": false,
            "hideInMenu": false
          }
        }
      ]
    }
  ],
  "home": "home"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| routes | `MenuRoute[]` | 嵌套树结构，children 递归；子路由相对路径自动拼接为绝对路径 |
| home | `string` | 默认首页路由名：取当前用户第一个配置了 home_path 的角色，缺省 `"home"` |
| MenuRoute.id | `string` | 菜单 ID（字符串化） |
| MenuRoute.component | `string \| null` | elegant-router 约定：`layout.xxx` / `view.xxx` / `layout.xxx$view.xxx`；旧数据 `Layout` 自动归一化为 `layout.base`，`ParentView` 归一化为 null |
| MenuRoute.meta.title | `string` | 菜单标题（无 i18nKey 时直接展示） |
| MenuRoute.meta.* | — | 可选：i18nKey / icon / localIcon（icon_type='2' 时）/ order / keepAlive / href / hideInMenu / activeMenu / multiTab / fixedIndexInTab / query（`[{key,value}]` 数组）/ constant |
