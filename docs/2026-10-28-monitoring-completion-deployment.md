# 监控与集成扩展部署验收

## 已实现范围

| 功能 | 当前支持 | 边界 |
| --- | --- | --- |
| 动态纳管 | CMDB 分组（含动态分组）或规则发现新主机，预览、确认、定时执行 | 不覆盖既有目标，不自动删除退出范围的主机 |
| 云资源目录 | 阿里云 RDS、Redis；腾讯云 MySQL、Redis | AWS、华为云尚无适配器 |
| 云指标与治理 | CPU 指标缓存、Prometheus 出口、余额与资源到期提醒 | 当前不是全量云监控指标；Prometheus 需要认证和授权 |
| JumpServer | 连接测试、选定主机预览确认、稳定映射、同步记录、定时同步 | SSH 主机；不接管外部同名资产，不删除远端资产 |
| 漏洞订阅 | 阿里云 AVD 公告、关键词和评级筛选、历史、通知去重重试 | 不执行漏洞扫描；未提供评级时显示“未评级” |

## 部署顺序

先备份数据库，按照项目现有部署流程安装锁定依赖，然后在 backend 目录执行：

```powershell
poetry run python manage.py migrate
poetry run python manage.py init_system_settings
```

新增迁移涉及 cmdb、monitoring、integrations、security。随后部署前端产物，重启 API、task 队列 Worker 和 Beat。仅重启 API 不会更新后台采集代码。

为使用人员补齐新菜单、按钮和 API 权限并重新登录。定时执行绑定执行人，停用、离职或撤销权限会阻止后续执行。不要为了导入菜单布局而覆盖管理员已经配置的图标和路径。

## 操作与验收

1. 动态纳管策略默认暂停，先预览再确认启用；修改配置后重新预览。单次范围最多 10000 台、每批最多新建 200 个有效目标，其余后续处理。暂停发现不会关闭已创建目标自身的自动同步。策略处理成功后，还需查看目标的实际 Consul 注册结果。
2. JumpServer 使用独立测试组织和 API Key，核对目标版本、节点和平台 ID。先预览一台 SSH 主机，再确认同步，重试应保持同一远端 UUID。已使用连接通过停用保留映射和记录；不自动删除远端资产。
3. 漏洞订阅首次成功采集只建立基线，不发送历史公告。后续新公告或内容变化触发通知。验证未知评级、过滤条件、源站结构变化和网络失败的记录。
4. 通知模板“变量说明与预览”选择对应场景。漏洞正文可用 `{{ advisory.title }}`、`{{ advisory.url }}`、`{{ advisory.severity }}`；标题可用 `{{ title }}`。预览采用示例数据，不发送消息。真实发送需要查看发送记录，进入队列不等于送达。
5. 验证停用账号、撤销权限、重复点击确认、并发任务、Worker 中断恢复。核对审计日志和通知记录的查看范围。

## 本轮复核修复与历史保留

- 纳管预览会在查询主机前核对 CMDB 读取权限；仅能查看策略不代表能读取主机详情。
- 云策略编辑在事务中重新锁定最新记录，保留后台推进的指标游标和排队时间；调度按排队时间轮询，每轮最多入队200条，已有执行中任务不占新任务配额。
- 到期时间明确清空时恢复对应告警；本次未返回资源或未返回到期字段时保留旧数据和告警。
- 云治理采集历史支持分页和云账号搜索。云资源、云治理采用统一搜索栏、普通单选和居中表格；旧请求不会覆盖新搜索结果。
- 云 API 错误记录按认证、权限、区域、超时、TLS、DNS、网络、限流等分类，保留脱敏错误码和请求 ID；不回显 SDK 原始报文。漏洞采集记录区分授权、源站读取、保存和通知阶段。

在 backend 目录预览历史保留效果（默认90天，每种记录最多1000条）：

```powershell
poetry run python manage.py purge_observability_history --days 90 --limit 1000
```

确认保留周期符合组织审计要求后，由运维在同一命令后加 `--execute` 执行；可通过现有运维调度每日调用，单次只处理指定批量。不删除排队或执行中的记录，不删除资产、纳管映射、漏洞去重观察、告警或通知发送记录。本次开发未对真实数据库执行清理。

部署这些修复无需新增数据迁移，但仍需重启 API、Worker 与 Beat，并部署更新后的前端。
