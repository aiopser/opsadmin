## 实施记录

- Ruling: 保留当前 dev2 工作区，不新建脱离既有未提交云同步代码的工作树，不自动提交。原因：交付复用本工作区尚未提交的身份和通知改造；新工作树将遗漏依赖。
- 新增独立 provisioning 应用、迁移、API、权限、模板版本与创建凭据管理。
- 已实现保存计划校验、确认与审批、本人审批拒绝、凭据与账号变更失效、幂等执行和中断结果核实。
- 已实现固定 CLI/Provider 锁文件、私有加密制品、创建范围检查、授权网络/镜像/规格限制、定向云回读与幂等纳管。
- 已接入模板、凭据、资源申请步骤条、详情、操作记录和通知变量预览。
- Ruling: 首期默认全部要求他人审批；不开放审批策略管理。避免在新子系统中同时引入未定义的组织审批策略。
- Ruling: 使用每申请隔离的 local state，加密归档并以数据库唯一 Attempt 和行锁限制执行；远端 backend 留后续部署方案。成本：部署需共享私有制品存储和工作目录备份，state 丢失须人工核实。
- Ruling: 主机资产快捷入口暂不修改，保留用户正在编辑的主机资产表；从任务系统资源申请进入。
- 独立审查指出“创建成功后回读重试错误覆盖执行结果”和“停用写凭据阻断只读纳管”，已修复并增加回归测试。审查代理随后因服务容量错误退出，未形成完整审查结论；剩余由主代理自查，不声称独立审查全部通过。
- 已观察到第一轮 contracts 缺模块失败，后转绿；私有制品与执行器测试先失败后转绿。
- 中间回归：资源交付、云同步、通知预览共 79 项通过。最终测试记录见本次最终报告与部署文档，避免把中间结果当最终结论。
- 完整后端回归：759 passed、6 skipped、25 subtests passed；第三方 django-celery-beat 两条 utcnow 弃用警告。
- 随后针对回读重试和排队时间边界修复，补充有效 API 创建和分页契约用例，最终 137 项关联回归通过。
