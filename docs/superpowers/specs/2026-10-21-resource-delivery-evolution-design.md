# 资源交付第二阶段设计

状态：用户已确认设计，前两项已细化为实施计划待审阅；本文不表示以下能力已经实现。

优先实施计划：[state 保护与运行保障](../plans/2026-10-21-provisioning-state-protection.md)、[云资源目录联动](../plans/2026-10-21-provisioning-cloud-catalog.md)。沿用当前会话直接实施，按顺序执行，不并行修改同一申请链路。

## 目标与交付顺序

在现有“模板 → 参数 → 计划 → 确认审批 → 执行 → 回读纳管”基础上，把资源交付扩展到可恢复、容易申请、可治理及可维护的完整生命周期。继续服务运维和没有专职运维的小团队，保持 Soybean Admin / Element Plus 既有视觉风格。

用户已确认五项业务范围及前两项优先级：

1. state 备份恢复、制品保留、Worker 监控、凭据最小权限。
2. 云 API 联动查询申请选项及可用性。
3. 环境审批、审批待办、配额、费用提示、负责人/项目/到期信息。
4. 已交付资源、变更、扩容、到期提醒与单独审批的销毁流程。
5. 按 VMware → OpenStack → PVE 顺序扩展私有云交付。

实施按上述五个可单独验收的交付阶段推进，不能以统一补几个页面代替能力交付。测试环境真实创建与浏览器验收此前未完成，本轮不假定已验收，也不自行启用生产资源写入。

## 已有代码与明确缺口

- `backend/apps/provisioning/terraform.py`：已有私有加密制品，缺少独立备份、版本索引、恢复校验和清理策略。
- `tasks.py`：已有排队/运行超时恢复，缺少持续心跳、Worker 健康视图及备份状态监控。
- `request-drawer.vue`：目前使用模板内保存的 ID 清单；不是云 API 实时目录。
- `models.py` / `services.py`：审批默认全部开启，尚无环境策略、项目配额及交付资源实体。
- `contracts.py`：仅允许 aliyun/tencent 的 create；`templates.py` 带 prevent_destroy。不能直接放宽这两个限制来实现扩容和销毁。
- 公有云读取依赖目前主要覆盖 ECS/CVM；网络目录需补充对应 VPC SDK 和权限。

## 方案选择

### A：延续单次申请并直接放宽 Terraform 操作

代码改动少，但历史申请、当前资源、state 和销毁职责混在一起；无法清楚识别这次审批绑定哪次资源状态。不采用。

### B：引入成熟的外部 Terraform 运行平台

可以复用远端 state 与运行治理，但会新增外部平台、授权和运维成本，当前项目没有已部署的目标平台。不作为本轮前提，保留适配点。

### C：扩展现有平台，分离交付资源与变更申请（选用）

保留现有创建申请和冻结计划；增加 state 版本、备份和健康能力，随后增加持久交付单元及专门的变更申请。Terraform 继续负责 plan/apply，SDK/API 负责只读目录、库存与实际结果核实。先完成前两项，再按同一契约扩展治理与生命周期。

## 第一阶段：上线保障

### state 版本与独立备份

- 新增 state 版本索引：交付/执行归属、版本号、lineage、serial、内容摘要、主制品键、备份键、加密 key ID、创建时间、校验时间及保护状态。API 不返回原始 state 或私有路径。
- 主副本与备份使用两个独立配置的私有存储位置。目录不同不代表故障域不同，部署验收必须核实独立卷/存储与备份密钥恢复能力。
- 写入采用临时文件、完整性校验、原子提交和持久化；备份成功后才标记“已保护”。不得先清理仅有的工作目录再尝试备份。
- 加密密钥引入版本标识与明确的密钥环；旧版本恢复不能因为仅保留当前密钥而失效。密钥材料不入数据库、不入备份包、不自动生成替代已丢失的密钥。
- apply 已成功但备份失败时，执行状态仍为成功，保护状态单独显示“备份异常”。允许只读纳管，阻止新的资源写变更，直到保护恢复。
- 在生成计划前检查存储可写及备份可用；执行完成后归档主 state、备份及元数据。主/备索引关联失败时保留待修复记录，不伪造成功。

### 恢复流程

“选择备份版本 → 校验归属、摘要、密钥和 lineage/serial → 展示核对结果 → 管理员确认恢复控制状态 → 只读云核实与漂移检查”。恢复 state 不执行 apply、不自动重新开机，也不声称回滚了云资源。

- 仅专门恢复权限可操作；普通申请者只能看到保护状态。
- 存在排队、运行或待核实的写任务时，禁止替换当前控制状态。
- 拒绝跨账号、跨交付单元、错误 lineage、摘要损坏、未知密钥版本及低于已知最新 serial 的自动恢复。
- 只有较旧备份且更新状态已丢失时，进入人工接管流程：先按已知实例 ID 和云标签核实归属，形成重新导入的计划与审核记录；不能用 force 覆盖掩盖版本落后。
- 恢复后旧计划、确认和审批全部失效。完成只读核实后才能生成新的变更计划。

### 制品保留

默认建议值：失效且没有未完成执行关联的原始 plan 保留 30 天；脱敏诊断制品 30 天；已销毁并核实完成的历史 state/备份 180 天；业务摘要与审计保留 365 天。活动资源的最新 state 及其可恢复备份、待核实资源的所有关键状态不按普通 TTL 删除。

清理任务先生成候选报告，再删除满足条件的对象。支持 dry-run、持有标记与清理审计；不能单凭文件 mtime 递归清空目录。用户的“增加保留策略”授权实现清理功能，不等于授权本次工具调用删除现有文件；实现测试仅使用隔离临时制品。

### Worker 健康与故障监控

- 新增专用执行器心跳及任务租约；默认 15 秒更新，90 秒未更新标记失联。无任务时也需 Worker 心跳，不能通过“最近没有失败任务”推断健康。
- 监控区分：无可用 Worker、队列积压、任务失联、CLI/Provider 不匹配、存储不可写、备份异常。
- 失联的写操作进入“结果待核实”，不重新投递 apply。超时终止应管理 Terraform 及子进程，不能只停止父进程后假定云侧未发生变化。
- 监控通知沿用现有渠道，按故障事件去重，恢复后可发恢复通知；未配置渠道仍保留平台事件。
- 增加受权限控制的交付运行状况视图，显示状态、最近心跳、排队量、异常申请与备份情况；不展示服务器私有路径、环境变量或密钥。

### 凭据最小权限

保持目录读取、资源创建、资源变更、资源销毁的应用权限分离，写凭据不自动获得销毁权限。提供与实际模板行为一致的云 IAM 权限清单及测试指引，不自动修改云 RAM/CAM 策略。

测试项包括：可查询但不可创建、可创建但不可销毁、越账号使用被拒、更新密钥使旧计划失效、未知 SDK/权限不足能显示操作及请求 ID。平台授权通过不代表云 IAM 已通过，界面应区分两类错误。

## 第二阶段：云资源目录与申请体验

### 目录契约

增加只读、分页的 catalog 接口，输入模板版本、云账号/创建凭据引用、地域、目录类型和依赖选择。服务端每次校验访问权限及模板授权范围后，再读取账号的只读凭据查询；不使用创建密钥为普通用户扩大可见范围。

目录类型：可用区、镜像、实例规格、VPC、子网/交换机、安全组、配额及可用性。统一字段包括 `id`、`name`、`description`、`available`、`unavailableReason`、`attributes`、`observedAt`；返回 `hasMore`/游标，不能把第一页当成完整清单。

前端选项展示：

- 镜像：名称、系统、架构，必要时显示 ID。
- 规格：名称或型号、CPU、内存、可用状态。
- 子网：名称、网段、可用区、可用 IP 数量（云 API 实际返回时）。
- 安全组：名称与 VPC 归属，详情能查看允许选择的规则摘要。
- 无名称时明确回退到 ID；售罄和不兼容选项禁选，并给出原因。

库存状态与精确库存数量区分。接口只返回“有库存/售罄”时，不能编造剩余台数；配额/余额查询失败或接口不提供时显示“未知/未返回”，不能显示 0 或“充足”。目录查询不保证执行时仍有资源，计划与执行前仍需校验。

### 授权清单与发现规则

云 API 查询结果必须与模板策略取交集，不能因为下拉框联动而扩大授权。保留首版明确 ID 清单的兼容方式；新版本支持管理员通过账号、地域、资源标签、镜像来源/系统/名称前缀及规格范围定义发现规则，减少逐个维护 ID。

规则为受控结构化字段，不执行用户提供的脚本、表达式或任意正则。流程提交时冻结实际解析出的 ID、关键显示属性与策略版本；后续目录变更不改写已有计划。

### 依赖与前端行为

选择账号/模板 → 地域 → 可用区 → 镜像与规格 → 网络与安全组。改变上游字段后清空不兼容的下游值，取消或忽略旧响应；不在后台保留上一账号的已选值。

- 普通目录缓存默认 120 秒，可用性默认 30 秒；缓存键包含账号、凭据配置版本、模板策略版本、地域和筛选条件，且命中缓存前仍执行权限校验。
- 显示最近读取时间并支持重新读取；权限错误、依赖缺失、限流、超时有区分提示及请求 ID。
- 新版目录模板若无法验证必要资源，不退回可任意输入的 ID；旧版静态模板保持兼容，不自动升级权限策略。
- 管理员模板配置也复用目录组件，减少手填 ID；申请页和配置页使用同样的名称、单位、空态与加载态。
- 所需 VPC SDK 明确加入依赖并锁定版本；不得依赖开发机偶然安装的包。

## 第三阶段：治理

### 业务归属与策略

申请增加环境、项目、负责人及可选到期时间。负责人为平台有效用户；项目采用独立轻量项目实体，包含可申请成员与配额，避免把任意文本当成权限边界。历史申请迁移到“未分配项目”，默认要求审批，不能自动归入测试环境以跳过审批。

环境策略由管理员维护：生产默认必须他人审批；测试/开发可按项目、数量和规格限制允许仅确认。未知环境默认需审批；本人审批保持禁止。策略变更触发尚未执行计划失效，前端不能通过 requires_approval 字段覆盖服务端策略。

### 配额与费用

- 配额包括项目活动主机数、总 vCPU、总内存、单次申请数量；没有显式配置可用配额的项目不能自助免审批创建。
- 生成计划与执行前校验，执行前在事务中预留额度，防止两个并发申请各自通过校验后超配。
- 已创建待纳管、部分成功、结果待核实的资源继续占用额度；只有核实未创建或已释放后才能退回。
- 费用优先使用厂商正式询价结果，注明币种、计费周期、获取时间和未覆盖项目；无报价时显示待询价及计费方式，不给出虚构金额，不把规格单价当整单费用。

### 待办与提醒

资源申请列表增加“我的申请 / 待我审批”，仅有审批资格者可见待办；详情先展示变更与影响，再展示动作。到期前默认 7 天、1 天通知负责人和项目配置的接收人；到期只提醒，不自动销毁。通知有幂等记录和发送失败检索。

## 第四阶段：资源生命周期

### 分离当前资源与历史申请

新增 `ResourceDeployment` 作为持续存在的交付单元，关联所属项目/账号、实例 ID、CMDB 资产、当前 state 版本及当前配置。原创建申请保持历史不可变；已成功、归属可核实的历史申请通过迁移形成交付单元，待核实申请先处理归属，不能自动接管手工创建的主机。

新增变更申请，操作类型区分 create、resize、scale_out、destroy，分别授权和审批。首期变更/销毁以完整交付单元为边界；多实例交付单元不暗中把“销毁一台”扩大为销毁全部。单实例独立接管/拆分另设明确迁移流程。

### 变更、扩容

所有变更先基于当前已保护 state 做刷新核实，再生成保存计划。审批绑定交付版本、state 摘要、目标资源集合及变更摘要，不能复用创建审批。

- 首期允许受控规格调整、磁盘增大、追加实例；禁止磁盘缩小和以降低数量隐式删除资源。
- 展示旧值 → 新值、可能重启/停机、关联磁盘和预计新增费用。
- 规格调整若被 Provider 计划为替换，拒绝普通扩容申请，不能按“扩容”直接删除重建主机。
- 同一交付单元串行写入；备份异常、state 未核实、有待确认漂移时阻止写操作。

### 销毁

单独权限、单独销毁申请、独立审批。页面明确列出全部实例及关联资源、数据保留选项和影响范围；生产必须他人审批，执行前再次输入交付名称确认。

保留首版创建模板的 prevent_destroy；销毁使用单独审核的生命周期配置及已确认的销毁计划，只接受该交付单元确实拥有且已批准释放的资源。发现范围外资源、不可归属磁盘或云侧删除保护时停止，不自动解除保护或附加 force 参数。

云 API 确认资源已释放后才更新交付终态、释放配额，将关联资产标记退役；不删除历史资产和审计。云侧结果未知时保留“待核实”，不能显示已销毁。

## 第五阶段：私有云交付

通过统一的 Provider 能力注册表扩展，替换各处硬编码的 aliyun/tencent 判断。注册表声明可读目录、可创建资源类型、可变更字段、销毁能力及回读标识，避免仅前端加选项但后端不可用。

| 平台 | 申请参数与目录 | 回读与边界 |
| --- | --- | --- |
| VMware | vCenter、数据中心、集群/资源池、Datastore、网络、已审核虚机模板、CPU/内存/磁盘 | 用 vCenter 范围内稳定虚机标识关联；不使用显示名称作唯一键 |
| OpenStack | 区域、Project、镜像、Flavor、Network/Subnet、安全组、卷 | 使用云账号/Project 与 Server UUID；明确卷随实例删除策略 |
| PVE | 集群、节点、存储、桥接网络、已审核 VM 模板、CPU/内存/磁盘 | 使用集群身份与 VMID；IP 未就绪时保留交付并等待纳管，不伪造 IP |

每个平台都需独立锁定、审核 Terraform Provider 与模板，使用对应只读 API 获取目录和实际结果。以“创建 → 回读 → 备份恢复 → 变更 → 审批销毁”逐项验收能力，尚未验收的平台/操作不显示可执行按钮，也不以“即将上线”占位冒充已接入。

VMware 先落地，再复制已验收的契约到 OpenStack、PVE。私有云网络、Datastore、Project 与节点权限按账号范围校验；不把公有云 region/vpc 参数强行套在所有平台上。配置表单由后端受控参数 Schema 和能力集合驱动，继续使用 Element Plus。

## 验收门槛

1. 主制品丢失后能从独立备份恢复；错误摘要、密钥、lineage、serial 和跨交付恢复均被拒绝；恢复不触发 apply。
2. apply 成功而备份失败不改写执行成功，也不能继续新的资源写操作；只读纳管可进行。
3. 清理 dry-run 保留活动 state、最新备份和待核实状态；正式清理只处理满足保留规则的对象并有审计。
4. 无 Worker、心跳中断、任务失联和备份异常能准确展示并去重通知；不重复创建资源。
5. 云目录分页、售罄、缺少库存数字、缺少名称、权限不足、限流、过期缓存均正确处理；账号切换没有旧选项串入。
6. 改动前端参数不能越过模板/账号授权；目录不扩大访问范围；云数据不进入新的历史计划。
7. 两个并发申请不会超配；未知结果和未纳管实例不提前退回配额。
8. 生产策略不能由前端跳过；审批待办不显示无资格的申请；到期提醒不自动销毁。
9. 规格调整的替换计划被拒；销毁不会触及归属不明资源，不自动解除删除保护；资产历史保留。
10. 三种私有云分别验证稳定身份、半成功、无 IP、API 回读延迟与恢复，不以公有云测试代替私有云验收。
11. 前端复用搜索栏、步骤条、抽屉、表格与状态规范，完成桌面/窄屏、长名称、错误态及加载态的真实浏览器验收。

- [Terraform state push](https://developer.hashicorp.com/terraform/cli/commands/state/push)：恢复需检查 lineage 和 serial，不采用自动 force 覆盖。
- [阿里云 DescribeAvailableResource](https://help.aliyun.com/zh/ecs/developer-reference/api-ecs-2014-05-26-describeavailableresource)：查询资源库存状态，不能据此假造精确剩余台数。
- [腾讯云 DescribeInstanceTypeConfigs](https://cloud.tencent.com/document/api/213/15749)：规格配置查询与库存、配额不是同一个概念，目录分别建模。
